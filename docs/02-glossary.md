# CTMS — Glossary & Acronyms

This document defines the domain vocabulary, acronyms, and technical terms used across the
Campus Transport Management System (CTMS) engineering documentation suite. It is the authoritative
reference for terminology: wherever another document uses a term below, the definition here governs.

Terms are listed alphabetically. Where two terms are frequently confused (for example **Schedule**
vs **Trip**, or **Consolidation** vs **Replacement**), a dedicated disambiguation section follows the
main table.

---

## How to use this glossary

- **Term** — the canonical spelling used in code, database columns, and prose. Entity names use
  PascalCase (e.g. `RouteStop`); enum values use `UPPER_SNAKE_CASE` (e.g. `ON_TRIP`); functional
  requirement identifiers use the `FR-01`..`FR-15` form.
- **Category** — quick classification: *Domain* (business concept / entity), *Enum* (fixed value set),
  *Tech* (platform / infrastructure), *Acronym*, or *Role*.
- **Definition** — a concrete, build-oriented explanation, cross-linked to the relevant functional
  requirement (FR) or entity where useful.

## A

| Term | Category | Definition |
|------|----------|------------|
| **Admin** | Role | Transport-department operator role (`UserRole.ADMIN`). Manages buses, routes, drivers and students; schedules trips; monitors the live fleet; approves bus-merge and replacement decisions; views reports. Extends the abstract `User` entity with `employeeId`, `designation`, `officePhone`. |
| **Announcement** | Domain | Broadcast message entity aimed at a defined `audience` (Enum) with `publishAt`/`expireAt` windows. Distinct from a **Notification**, which targets a single receiving user. |
| **API Response Time** | Tech / NFR | Non-functional performance target: REST API responses complete in **under 2 seconds** under normal load. |
| **Audit Log** | Tech / Security | Immutable record of security-relevant actions (logins, approvals, assignments, status changes). Required by the security NFR alongside HTTPS and role-based authorization. |
| **Availability** | Tech / NFR | Uptime target of **99.9%** for the CTMS backend and tracking services. |
| **Available** | Enum | Value in both `BusStatus.AVAILABLE` (bus is idle and assignable) and `DriverStatus.AVAILABLE` (driver is free to be assigned to a trip). |
| **averageSpeed** | Domain | Attribute on `Trip` (Double) recording the mean speed across the trip, derived from `TripLocation` samples; used in ETA and delay analytics. |

## B

| Term | Category | Definition |
|------|----------|------------|
| **Board** | Enum | `PassengerLog.action` value indicating a passenger boarded the bus (driver pressed **+1**). Paired with **Exit**. See **Passenger Log**. |
| **Breakdown** | Enum | `BusStatus.BREAKDOWN` — the bus has failed mechanically mid-service and is unavailable. Typically follows a **Vehicle Incident** and triggers the **Replacement Bus** workflow (FR-11 → FR-12). |
| **Bus** | Domain | Core vehicle entity. Key fields: `busNumber`, `registrationNumber`, `chassisNumber`, `engineNumber`, `capacity`, `currentPassengers`, `gpsDeviceId`, `status` (`BusStatus`), plus service/insurance/permit expiry dates. Managed under FR-02. |
| **Bus Consolidation** | Domain | See **Smart Bus Consolidation** and the **Consolidation vs Replacement** disambiguation below. |
| **BusMergeRecommendation** | Domain | Entity generated by FR-13. Links a `sourceTripId` and `targetTripId`, records `sourcePassengers`, `targetPassengers`, `mergedPassengers`, `estimatedFuelSaved`, `distanceIncrease`, a `status` (Enum) and `approvedBy` (admin FK). Requires admin approval to take effect. |
| **BusStatus** | Enum | Lifecycle state of a bus: `AVAILABLE`, `RUNNING`, `MAINTENANCE`, `BREAKDOWN`, `OFFLINE`. |
| **Business Rule** | Domain | A hard invariant the system must enforce (e.g. passenger count must never exceed capacity; one active driver per bus per trip; a bus in maintenance cannot be assigned). See the Business Rules section of the SRS. |

## C

| Term | Category | Definition |
|------|----------|------------|
| **Capacity** | Domain | Maximum seated/standing passengers a `Bus` may carry. Enforced business rule: `currentPassengers` must never exceed `capacity` (FR-08). |
| **Consolidation** | Domain | Short form of **Smart Bus Consolidation** (FR-13) — merging two low-occupancy trips onto one bus to save fuel. Not to be confused with **Replacement**. |
| **CTMS** | Acronym | **Campus Transport Management System** — the centralized platform for a college to manage buses, drivers, routes, trips and students with real-time tracking, notifications, incident handling and transport optimization. |
| **currentPassengers** | Domain | Live occupancy counter on `Bus`, kept in sync with the active trip's `passengerCount` via the passenger counter (FR-08). |

## D

| Term | Category | Definition |
|------|----------|------------|
| **Delay** | Domain | Difference between expected and actual timing. Stored as `Trip.delayMinutes` (int); triggers a delay **Notification** to students (FR-10). |
| **Docker** | Tech | Containerization platform used for CTMS deployment; the backend, Reverb and supporting services run as containers behind **Nginx**. |
| **Driver** | Role / Domain | Operator of a bus (`UserRole.DRIVER`). Extends `User` with `employeeId`, `drivingLicenseNumber`, `licenseExpiry`, `aadhaarNumber`, `assignedBusId`, `available`, `status` (`DriverStatus`). Can start/end trips, share GPS, adjust passenger count, report issues and send **SOS**. |
| **DriverStatus** | Enum | Availability state of a driver: `AVAILABLE`, `ON_TRIP`, `LEAVE`, `OFF_DUTY`. |

## E

| Term | Category | Definition |
|------|----------|------------|
| **ETA** | Acronym / Domain | **Estimated Time of Arrival** — predicted time a bus reaches a student's stop, computed from live GPS position and the **Google Routes API** (FR-09). Surfaced to students in the Student app. |
| **Exit** | Enum | `PassengerLog.action` value indicating a passenger left the bus (driver pressed **−1**). Paired with **Board**. |
| **estimatedFuelSaved** | Domain | Decimal field on `BusMergeRecommendation` quantifying the fuel savings a proposed consolidation would yield; a key input to the admin's approve/reject decision. |

## F

| Term | Category | Definition |
|------|----------|------------|
| **FCM** | Acronym / Tech | **Firebase Cloud Messaging** — Google's push-notification transport used to deliver CTMS **Notifications** to Student and Driver mobile apps (FR-10). |
| **Fleet** | Domain | The complete set of buses operated by the college; the admin dashboard's live-fleet view shows every `RUNNING` bus in real time. |
| **FR-01 … FR-15** | Domain | **Functional Requirement** identifiers from the SRS (Authentication through Reports). Referenced throughout the docs; always cited in the exact `FR-0N` form. |

## G

| Term | Category | Definition |
|------|----------|------------|
| **Geofence** | Domain / Tech | A virtual circular boundary around a `RouteStop`, sized by `geofenceRadius` (Double, metres). When a bus's GPS position enters the geofence, the system fires the "bus nearing stop" event and notification (FR-10). |
| **geofenceRadius** | Domain | Radius (Double, metres) of a stop's **Geofence**, stored on `RouteStop`. |
| **Google Maps SDK** | Tech | Google mapping toolkit embedded in the mobile apps and dashboard for map rendering and live bus display. |
| **Google Places API** | Tech | Google service used for place lookup/autocomplete when defining route sources, destinations and stop landmarks. |
| **Google Routes API** | Tech | Google directions/ETA service that powers **ETA Calculation** (FR-09). |
| **GPS** | Acronym | **Global Positioning System** — satellite positioning that supplies each bus's live coordinates via the driver device. |
| **GPS Ingest** | Tech | The backend pipeline that receives GPS updates (every **5–10 seconds**, FR-07), persists them as `TripLocation` rows, updates live state via **Reverb** WebSockets, and buffers offline points for later sync (reliability NFR). |

## H

| Term | Category | Definition |
|------|----------|------------|
| **heading** | Domain | Compass bearing (degrees) of a bus at a given GPS sample, stored on `TripLocation`; used to orient the bus marker on the map. |
| **HTTPS** | Tech / Security | Encrypted transport mandated for all CTMS API and WebSocket traffic (security NFR). |

## I

| Term | Category | Definition |
|------|----------|------------|
| **Incident** | Domain | Short form of **Vehicle Incident** — a driver-reported fault (breakdown, accident, tyre puncture, engine issue, battery issue) captured as a `VehicleIncident` (FR-11). Every incident automatically spawns a **Maintenance Ticket** (FR-14). |
| **issueType** | Domain | Field on `VehicleIncident` categorizing the fault (breakdown, accident, tyre puncture, engine issue, battery issue). |

## J

| Term | Category | Definition |
|------|----------|------------|
| **JWT** | Acronym / Tech | **JSON Web Token** — signed, stateless token format for authenticating API requests. Used alongside Laravel **Sanctum** to secure role-based access (FR-01). See **Sanctum**. |

## L

| Term | Category | Definition |
|------|----------|------------|
| **Laravel 12** | Tech | PHP framework running the CTMS backend REST API and business logic. |
| **Laravel Reverb** | Tech | See **Reverb**. |
| **Live GPS Tracking** | Domain | Real-time display of bus position, refreshed every 5–10 s (FR-07). Powered by **GPS Ingest** and **Reverb**. |

## M

| Term | Category | Definition |
|------|----------|------------|
| **Maintenance** | Enum / Domain | (1) `BusStatus.MAINTENANCE` — a bus undergoing service; business rule: it **cannot be assigned** to trips. (2) The maintenance management module (FR-14) that manages **Maintenance Tickets**. |
| **Maintenance Ticket** | Domain | `MaintenanceTicket` entity auto-created from a **Vehicle Incident** (FR-14). Fields: `incidentId`, `busId`, `ticketNumber`, `assignedTechnician`, `status` (Enum), `repairStart`, `repairEnd`, `estimatedCost` (Decimal), `remarks`. One-to-one with its originating incident. |
| **Merge** | Domain | Colloquial term for **Smart Bus Consolidation** (FR-13); the recommendation record is a `BusMergeRecommendation`. Requires admin approval. |
| **mergedPassengers** | Domain | Field on `BusMergeRecommendation` — the combined passenger count after a proposed merge; must not exceed the target bus's capacity. |
| **mileage** | Domain | Decimal fuel-efficiency attribute on `Bus`, used in fuel-saving estimates for consolidation. |

## N

| Term | Category | Definition |
|------|----------|------------|
| **Nginx** | Tech | Reverse proxy / web server fronting the Dockerized CTMS services, terminating HTTPS and routing to the Laravel app and Reverb. |
| **Notification** | Domain | `Notification` entity delivered to a single user (`receiverId`). Carries `title`, `message`, `type` (Enum), `isRead`, `sentAt`; delivered via **FCM** (FR-10). Contrast with **Announcement** (audience-wide). |
| **NFR** | Acronym | **Non-Functional Requirement** — quality attributes: performance, availability, security, scalability, reliability. |

## O

| Term | Category | Definition |
|------|----------|------------|
| **Occupancy** | Domain | The number of passengers currently on a bus relative to capacity; low occupancy across two trips is what triggers a **Consolidation** recommendation. |
| **Offline** | Enum | `BusStatus.OFFLINE` — the bus's GPS device is not reporting; the bus is effectively untracked. |
| **Offline GPS Buffering** | Tech / NFR | Reliability feature: the driver app stores GPS points locally when connectivity drops and **automatically synchronizes** them to **GPS Ingest** when the connection returns. |
| **ON_TRIP** | Enum | `DriverStatus.ON_TRIP` — the driver is currently operating an active trip. |

## P

| Term | Category | Definition |
|------|----------|------------|
| **Passenger Counter** | Domain | Driver-app feature (FR-08) to increment/decrement live occupancy with **+1 / −1** buttons. Each press writes a **Passenger Log** entry and updates `Bus.currentPassengers`; blocked from exceeding `capacity`. |
| **Passenger Log** | Domain | `PassengerLog` entity: an audit trail of boarding events. Fields: `tripId`, `action` (`Board`/`Exit`), `countAfterAction`, `timestamp`. |
| **passengerCount** | Domain | Running occupancy figure held on `Trip` (and mirrored on `Bus.currentPassengers`). |
| **PostgreSQL** | Tech | Primary relational database for CTMS; stores all core entities with UUID primary keys and snake_case columns. |
| **Push Notification** | Domain | A notification delivered to a mobile device via **FCM**; see **Notification** and FR-10. |

## R

| Term | Category | Definition |
|------|----------|------------|
| **RBAC** | Acronym / Security | **Role-Based Access Control** — authorization model granting permissions by `UserRole` (`ADMIN`, `DRIVER`, `STUDENT`). Enforces rules such as "students can only view their assigned bus" (FR-01, security NFR). |
| **Redis** | Tech | In-memory cache used for hot data (live positions, ETAs, session/rate-limit state) to keep API responses under the 2 s target. |
| **Replacement** | Domain | Short form of **Replacement Bus** / `ReplacementAssignment` (FR-12); substituting a functioning bus for one that has broken down. Requires admin approval. Distinct from **Consolidation**. |
| **ReplacementAssignment** | Domain | Entity created by FR-12: `incidentId`, `replacementBusId`, `replacementDriverId`, `etaMinutes`, `assignedAt`, `status` (Enum). Recommended by the system, approved by an admin. |
| **Reports** | Domain | Operational reports and analytics module (FR-15): trips, delays, occupancy, incidents, fuel savings, etc. |
| **Reverb** | Tech | **Laravel Reverb** — the first-party WebSocket server that pushes real-time updates (live GPS positions, ETAs, notifications, status changes) to the Student/Driver apps and admin dashboard. |
| **Route** | Domain | `Route` entity: `routeCode`, `routeName`, `source`, `destination`, `totalDistance`, `estimatedDuration`, `active`. Owns one-to-many `RouteStop`s and `Schedule`s (FR-05). |
| **RouteStop** | Domain | Ordered stop on a route: `stopName`, `landmark`, `latitude`, `longitude`, `sequence`, `geofenceRadius`, `expectedArrival`. |
| **Running** | Enum | `BusStatus.RUNNING` / `TripStatus.RUNNING` — the bus/trip is actively in service. |

## Disambiguation notes

### Schedule vs Trip

These are the two most-confused entities. Keep them strictly separate in code and prose.

| Aspect | **Schedule** | **Trip** |
|--------|--------------|----------|
| Nature | Recurring **plan / template** | Single **concrete execution** |
| Time granularity | `dayOfWeek` + `departureTime`/`arrivalTime` | Specific `tripDate` + real `startTime`/`endTime` |
| Cardinality | One schedule generates **many** trips | Each trip derives from at most one schedule (`scheduleId`) |
| Mutable during run? | No — static configuration | Yes — accrues `TripLocation`, `PassengerLog`, `delayMinutes`, status |
| Owner action | Admin creates it (FR-05/FR-06 setup) | Driver starts/ends it (FR-06 execution) |

**Rule of thumb:** if it happens *every Monday at 8:00*, it is a **Schedule**; if it happened
*on 2026-07-10 and carried 34 passengers*, it is a **Trip**.

### Consolidation (Merge) vs Replacement

Both are optimization/continuity workflows that require **admin approval**, but they solve opposite problems.

| Aspect | **Smart Bus Consolidation** (FR-13) | **Replacement Bus** (FR-12) |
|--------|-------------------------------------|-----------------------------|
| Trigger | Two trips with **low occupancy** | A **Vehicle Incident** / breakdown |
| Goal | Save fuel by merging passengers onto one bus | Restore service after a failure |
| Record | `BusMergeRecommendation` | `ReplacementAssignment` |
| Key inputs | `estimatedFuelSaved`, `distanceIncrease`, `mergedPassengers` | `replacementBusId`, `replacementDriverId`, `etaMinutes` |
| Constraint | Merged count must fit target `capacity` | Replacement bus must not be in `MAINTENANCE` |
| Outcome | One bus stood down, one continues | Broken bus removed, fresh bus dispatched |

### Notification vs Announcement

| Aspect | **Notification** | **Announcement** |
|--------|------------------|------------------|
| Target | A single `receiverId` (one user) | A broad `audience` (Enum) |
| Lifecycle | `isRead`, `sentAt` | `publishAt`, `expireAt` |
| Transport | Push via **FCM** | Posted/broadcast, time-boxed |
| Example | "Your bus is nearing your stop" | "No transport service on Republic Day" |
